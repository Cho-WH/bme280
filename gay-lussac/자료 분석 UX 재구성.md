# 자료 분석 UX 재구성

작성일: 2026-10-13 · 용도: 자료 분석 UX 구현 기준

사용자의 UX 제안과 확정 사항을 현재 코드에 맞춰 정리한 구현 기준이다. 온도·기압 좌우 축, 결과 해석의 고정 축, 사용자가 켜는 추세선·연장을 반영한다. 현재 구현·검증 현황과 후속 범위는 [README](README.md)를 기준으로 한다.

## 1. 구현 방향

**기존 분석 엔진을 유지하고, 자료를 보는 순서와 조작 위치를 재구성한다.** 계산 열, 선형회귀, 분석 제외·복원, 이력, CSV·JSON·PNG 출력은 이미 있다. 새로 구현할 핵심은 시간 그래프의 구간 선택과, 분석 범위를 기준으로 한 일관된 상태 표시다.

처음에는 실험 전체의 변화를 보여 주고, 학생이 전체 자료 또는 직접 고른 구간으로 관계를 살펴보게 한다. 숫자표는 필요할 때 펼치는 보조 도구로 바꾼다. 구간 추천, 자동 이상치 제거, 관계에 대한 자동 결론은 추가하지 않는다.

제안문에 실제로 나열된 작업 메뉴는 **원 자료 보기 / 관계 그래프 / 결과 해석의 세 개**다. 단계 잠금이나 완료 조건을 두지 않고 모두 처음부터 누를 수 있게 한다. 기존의 ‘표 / 표·그래프 / 그래프’는 이 상단 메뉴에서 내려오고, 각 작업 안의 표 펼침·접기로 대체한다.

## 2. 우선 구현 범위

| 구분 | 구현할 내용 |
|---|---|
| 1차 핵심 | 시간에 따른 온도·압력 전체 그래프, 함께 읽는 커서, 접힌 표, 두 가지 시작 버튼 |
| 1차 핵심 | 그래프의 양 끝 손잡이·시간 입력, 미리 선택한 구간과 확정한 분석 범위의 분리 |
| 1차 핵심 | 축 즉시 변경, 관계 그래프와 함께 보이는 표·추세선·계산 열 도구 |
| 1차 핵심 | 범위·제외·유효값 개수의 일관성, 점 정보·행 강조, 제외·복원·되돌리기 |
| 1차에 함께 연결 | 기존 회귀·직선 연장·다운로드를 모은 최소한의 결과 해석 화면, 계산 열 미리보기의 입력값 병기 |
| 후속 | 관찰한 관계·판단 근거 글쓰기와 저장, 상세한 해석 설명, 고급 계산 편집기 |

세 메뉴를 한 번에 제공하므로 결과 해석을 빈 화면으로 두지 않는다. 다만 1차에서는 이미 있는 회귀 결과와 저장 기능을 연결하는 수준으로 제한한다. 글쓰기 기능을 위해 저장 구조를 먼저 확장하지 않는다.

## 3. 화면과 이동

### 3.1 공통 영역

상단에는 실험 이름과 작은 `자료 n개`를 두고, 아래에 세 작업 메뉴를 둔다. 여기서 n은 현재 분석 화면에 불러온 원자료 수다. 아직 불러오지 않은 새 수신 자료는 기존 방식대로 별도로 알린다.

확정 범위와 분석 포함·제외 개수는 세 메뉴에서 같은 요약을 사용한다. 원 자료 보기에서 손잡이를 조절할 때의 초안 개수는 확정된 요약과 구별해 표시한다.

새로 측정을 마치거나 CSV를 열면 ‘원 자료 보기’부터 시작한다. 저장된 실험이나 JSON을 열 때도 첫 화면은 전체 모습으로 하되, 기존 분석 범위·제외·계산 열·축 설정은 그대로 복원한다. 같은 실험 안에서 메뉴만 오갈 때는 펼침 상태와 미적용 구간 초안을 화면 상태로 유지한다.

관계 그래프 메뉴를 바로 누르면 이미 확정된 범위로 연다. 작업 이력이 없는 새 자료는 전체 범위와 온도–압력 축을 기본으로 사용한다. 구간 선택이나 표 체크를 선행 조건으로 삼지 않는다.

축 정의가 없으면 공통 기본 그래프의 표시 모델로 시작한다. 실제 축 변경·추세선 조작 때 Workspace에 정의를 저장하며, 메뉴 방문만으로 기본값을 따로 저장하지 않는다.

### 3.2 원 자료 보기

```text
실험 이름                                      자료 5,000개
원 자료 보기       관계 그래프       결과 해석

             시간에 따른 온도·압력 전체 그래프
             온도: 왼쪽 축 / 압력: 오른쪽 축

[전체 자료로 관계 보기]   [구간 골라 분석하기]
▸ 측정값 표 보기
```

- 측정 화면의 이중 축 시간 그래프를 전체 범위 모드로 재사용한다. 두 물리량은 색·축 이름·단위로 구분한다.
- 세로 커서는 가까운 **하나의 실제 측정 자료**를 기준으로 시각·온도·압력을 함께 보여 준다. 서로 다른 시점의 온도와 압력을 합치거나 없는 값을 보간하지 않는다. 값이 없으면 `—`와 이유를 표시한다.
- 현재 차트의 수신 공백·시각 역행에 따른 선 끊김을 유지한다. 커서가 공백 위에 있을 때 실제로 가리킨 측정 시각이 분명해야 한다.
- 표는 기존 가상 스크롤 표를 접은 상태로 둔다. 펼쳐도 원자료 그래프와 시작 버튼은 유지한다.
- ‘전체 자료로 관계 보기’는 현재 불러온 전체를 분석 범위로 확정하고 관계 그래프로 이동한다. 기존 제외 표시는 유지한다. 범위를 전체로 바꾸는 것과 제외를 취소하는 것은 별개의 조작이다.
- 기본 축은 온도(℃)–압력(hPa)이다. 기존 그래프 설정이 있으면 학생이 바꾼 축을 유지한다.

### 3.3 구간 고르기

‘구간 골라 분석하기’를 누르면 같은 그래프 위에 반투명 선택 영역과 양 끝 손잡이를 표시한다. 처음에는 전체를 덮고, 이미 시간 구간을 확정한 작업이라면 그 위치에서 시작한다. 영역 밖을 흐리게 하되 전체 자료의 모양은 남긴다.

```text
시작 [경과 시간(초)]   끝 [경과 시간(초)]   선택한 자료 420개
[전체 구간]   [취소]                      [이 구간으로 분석]
```

- 손잡이와 시간 칸은 같은 초안을 수정한다. 내부 비교는 원자료의 `receivedAt` 시각을 사용하고, 입력은 첫 기록 기준 경과 시간으로 표시한다. 실제 시작·끝 시각도 함께 보여 준다. 자정을 넘으면 날짜를 포함한다.
- ‘전체 구간’은 초안을 전체로 되돌린다. ‘이 구간으로 분석’을 눌러야 실제 범위가 바뀐다. ‘취소’는 초안을 버리고 현재 확정 범위를 유지한다.
- 선택을 시작하면 두 시작 버튼 대신 구간 조작을 보여 주고, 주 실행 버튼은 ‘이 구간으로 분석’으로 바뀐다. 확정 전에는 `선택 중 · 아직 분석에 적용하지 않음`을 짧게 표시한다.
- 확정은 범위 저장과 필요한 기본 그래프 설정을 하나의 작업으로 처리한다. Workspace가 변경을 받아들인 뒤 관계 그래프로 이동한다. 이후 DB 저장 상태·실패·재시도는 기존 저장 표시를 따른다.
- 선택 자료 수는 구간 안의 전체 건수다. 기존 제외 자료가 있으면 `선택한 자료 420개 · 제외 2개`처럼 함께 표시한다.
- 사용자가 좋은 구간을 판단한다. 앱이 안정 구간이나 높은 R²를 기준으로 손잡이를 자동 배치하지 않는다.

### 3.4 관계 그래프

```text
분석 포함 418개 · 제외 2개 · 20.0–80.0초           [구간 수정]
가로축 [온도 (℃) ▾]       세로축 [압력 (hPa) ▾]

┌────────────────┬─────────────────────────┬──────────────┐
│ 펼친 경우의 표 │       큰 관계 그래프    │ 추세선       │
│                │                         │ 표 보기      │
│ 계산 열 추가   │                         │ 표시 설정    │
└────────────────┴─────────────────────────┴──────────────┘
             회귀에 사용한 자료 수 · 기울기 · y절편 · R²
```

- 축은 그래프 위의 짧은 줄에 둔다. 자주 쓰는 보조 도구는 오른쪽에 모으고, 계산 열 추가는 펼친 표의 도구 줄에 둔다. ‘계산 열’ 바로가기를 도구 영역에 둘 경우 같은 편집기를 열도록 연결한다.
- 축의 선택이 바뀌면 기존 `Workspace.setGraph()`로 즉시 반영한다. ‘만들기/적용’ 버튼과 별도 축 초안을 없앤다. 유효하지 않은 변경은 원래 축을 유지하며 해당 위치에 이유를 표시한다.
- 현재 지원하는 온도·압력·가져온 숫자 열·계산 열을 재사용하고, 수신 시각은 기존처럼 가로축에서 제공한다. 지원 물리량을 확대하거나 임의의 텍스트 열까지 허용하는 작업은 포함하지 않는다.
- ‘구간 수정’은 원 자료 보기의 선택 모드를 연다. 확정해 둔 손잡이 위치가 복원되며, 다시 확정할 때까지 관계 그래프의 분석 범위는 유지한다.
- 표를 펼쳐도 그래프·추세선·축·오른쪽 도구는 유지한다. 기존 압축 표를 기본으로 쓰되 전체 열을 보는 수단과 계산 열 추가 진입점을 제공한다. 열을 만든 뒤에는 해당 열을 확인할 수 있게 하고 그래프 축은 자동 변경하지 않는다.
- 좁은 화면은 세 칸을 억지로 유지하지 않는다. 그래프와 도구를 먼저 놓고 표를 아래에 펼치되 같은 Workspace와 표 엔진을 사용한다.

### 3.5 결과 해석

가로축은 **온도(℃)**, 세로축은 **기압(hPa)**으로 고정한다. 관계 그래프에서 선택한 축을 덮어쓰지 않고, 같은 확정 범위·제외 자료로 고정 축 표시 모델을 만든다. 원자료 배열이나 회귀 엔진을 별도로 복제하지 않는다.

- 결과 해석의 추세선·직선 연장은 처음에 모두 꺼져 있다. 학생이 각 토글을 켜며, 메뉴 방문 자체로 선을 표시하거나 연장하지 않는다.
- 두 설정은 Workspace의 `interpretation: { enabled, view }`에 저장한다. 관계 그래프의 축·추세선·연장 설정은 유지하여 돌아왔을 때 탐색을 이어갈 수 있게 한다.
- 추세선을 켜면 현재 고정 축의 유효 자료로 회귀한다. x절편을 계산할 수 있을 때만 직선 연장을 켤 수 있다. 측정 범위 밖은 점선으로 표시한다.
- 자료 수 부족·기울기 0 등에서는 계산 가능한 결과와 불가 이유를 보여 준다. 메뉴 진입은 막지 않으며 자동으로 자료를 제외하지 않는다.
- 그래프 아래에 회귀 자료 수·기울기·y절편·R²와 단위를 표시한다. 이 화면은 식·x절편의 상세를 기본으로 펼치고 의미 설명은 접어 둔다.
- x절편은 절대영도 추정을 위한 근거로 설명하되 측정 범위 밖의 추정임을 표시한다. 높은 R²만으로 비례 관계나 측정 정확도를 판정하지 않는다.
- 학생이 쓰는 ‘관찰한 관계’, ‘그렇게 판단한 근거’ 칸과 고급 계산 편집기는 후속으로 둔다.

아래에는 `그래프 이미지 저장`, `분석 자료 CSV 저장`, `나중에 이어하기용 파일 저장`을 둔다. 마지막 버튼에 `JSON`을 보조 표기로 붙인다. PNG는 현재 보고 있는 고정 축·토글 상태를 반영한다. 전체 원자료 CSV는 기존 다운로드 메뉴에 남기고 파일 형식과 저장 내용은 유지한다.

## 4. 기존 도구를 다듬는 범위

### 추세선

현재 선형회귀·입력 변경 시 자동 갱신·계산 불가 처리·직선 연장을 그대로 사용한다. 그래프 아래에는 회귀에 실제 사용한 자료 수, 기울기, y절편, R²를 먼저 표시하고 식·x절편은 상세 보기로 넘긴다. 결과 해석에서는 식을 기본으로 펼쳐 보여 줄 수 있다.

기울기는 세로축 단위/가로축 단위, y절편은 세로축 단위, x절편은 가로축 단위로 표시한다. R²는 무차원이다. 예를 들어 온도–압력의 기울기는 `hPa/℃`, y절편은 `hPa`다. 시간축의 회귀는 기존처럼 첫 유효 사용점 기준 경과 시간(초)을 사용하고 그 기준 시각을 함께 적는다. 계산 열의 단위가 비어 있으면 단위를 추측하지 않는다.

현재 화면·PNG가 공유하는 `trend-summary.js`를 항목별 요약까지 제공하도록 확장한다. 같은 수치를 화면마다 다시 계산하거나 문구를 별도로 관리하지 않는다.

### 계산 열

기존 추가 메뉴·템플릿·편집 대화상자·계산 엔진·검증·삭제 방지·이력을 재사용한다. 1차 수정은 **진입 위치와 미리보기**다.

현재 미리보기는 자료 ID와 계산 결과 중심이다. 식이 참조하는 입력값을 함께 반환·표시하도록 확장하여, 예를 들면 `온도 21.3℃ → 결과 294.45K`를 몇 행 확인할 수 있게 한다. 첫 몇 행을 대표값처럼 추려 보여 주지 않고 실제 미리보기 행의 값을 사용하며, 계산 불가 값도 이유와 함께 남긴다.

‘열 만들기’는 기존 `saveColumn()`을 호출한다. 현재 그래프와 축을 유지하고 새 열을 표와 축 목록에 추가한다. 현재 적용 범위에 미리 볼 행이 없으면 그 사실을 알리고, 식·이름 검증과 미리보기 가능 여부를 구분한다. 수식 언어 확대, 단위 자동 추론, 새로운 편집기 라이브러리는 필요하지 않다.

### 점 정보·제외·복원

점 클릭은 이제 체크 토글 대신 정보창을 연다. 시각·온도·압력과 현재 축의 값, 분석 상태를 표시한다. 표가 열려 있으면 같은 `sampleId`의 행에 **확인 중 강조**를 표시한다. 이것은 일괄 조작용 체크와 별개다.

정보창의 ‘분석에서 제외’는 기존 `exclude()`를 호출하고, 점은 옅은 빈 원으로 남긴다. 제외된 점에는 ‘분석에 다시 포함’을 제공한다. 선택적 사유는 정보창 안에서 입력할 수 있게 하되 빈칸으로도 즉시 제외할 수 있다. 1차에는 제외 실행 때 함께 저장하는 기존 방식을 사용하고, 사유만 사후 편집하는 별도 기능은 추가하지 않는다.

표 위의 일괄 작업 막대는 체크된 행이 있을 때만 표시한다. 예: `3개 선택 · 분석에서 제외 · 분석에 다시 포함 · 선택 해제`. 체크는 조작 대상이며 분석 범위가 아니다. 새 화면에서는 체크한 행을 분석 범위로 확정하는 진입점을 제공하지 않는다. 기존 파일의 지정 ID는 보존한다.

제외 직후 `1개를 제외했어요 · 되돌리기`를 잠깐 표시하고 기존 이력을 사용한다. 다른 작업이 이력에 추가되면 이전 알림의 되돌리기 동작을 종료하여 엉뚱한 최신 작업을 취소하지 않게 한다. 기존 상시 이력 버튼으로도 복원할 수 있다.

## 5. 범위와 상태의 단일 기준

가장 중요한 변경이다. 현재 표는 분석 범위 밖 자료도 제외되지 않았으면 ‘사용’으로 표시한다. 그래프와 CSV는 이미 적용 ID와 제외 ID를 따르므로, 표의 문구만 바꾸는 것으로는 충분하지 않다.

### 5.1 구별할 상태

| 상태 | 의미·소유 위치 | 변경 시점 |
|---|---|---|
| 불러온 자료 | Workspace가 읽은 원자료 스냅샷 | 기존 ‘새 자료 보기’를 실행할 때 |
| 구간 초안 | 화면에서 조절 중인 시작·끝 시각 | 손잡이·시간 입력. 저장·회귀 입력은 변경하지 않음 |
| 확정된 분석 범위 | Workspace의 `appliedIds` | 전체 자료 또는 구간 분석을 확정할 때 |
| 제외 자료 | Workspace의 `exclusions` | 제외·복원 명령을 실행할 때 |
| 체크한 자료 | Workspace의 `selectedIds` | 표에서 일괄 조작 대상을 고를 때 |
| 확인 중인 자료 | 화면의 `focusedSampleId` 등 표시 상태 | 그래프 점이나 표 행을 확인할 때. 저장하지 않음 |
| 표 필터·정렬 | 기존 표 정의 | 표시 행·순서만 변경. 분석 범위를 변경하지 않음 |

표·그래프·상단 요약·CSV가 각자 분석 ID를 만들지 않게 한다. 공통 순수 함수에서 **범위 포함 여부와 제외 여부**를 판정하고, 화면과 파일 어댑터가 같은 정의를 소비하도록 정리한다. DB에 상태별 복사 배열을 추가하지 않는다.

### 5.2 행 상태와 수치

| 원자료의 상태 | 표의 기본 표시 | 관계 그래프·회귀·분석 CSV |
|---|---|---|
| 범위 안, 제외 아님 | 분석 포함 | 현재 축의 값이 유효하면 점·회귀에 사용. CSV에는 포함 |
| 범위 안, 제외됨 | 제외 | 그릴 수 있는 점은 빈 원. 회귀·분석 CSV에서는 제외 |
| 범위 밖 | 범위 밖 | 관계 그래프·회귀·분석 CSV에 포함하지 않음 |

범위 밖 자료에도 과거의 제외 정보가 남아 있을 수 있다. 기본 상태는 ‘범위 밖’으로 표시하되 제외 기록·사유는 상세 정보에서 확인하고 복원할 수 있게 한다. 구간을 다시 넓혔다고 제외가 저절로 취소되지 않는다.

상단 `분석 포함`은 범위 안에서 제외하지 않은 행 수다. 실제 그래프 점과 회귀에 쓸 수 있는 자료 수는 현재 두 축의 값 유효성에 따라 더 적을 수 있다. 차이가 있을 때 `현재 축의 값 없음 2개 · 그래프 416개`처럼 설명하고, 추세선 아래에는 실제 회귀 입력 수를 적는다.

분석 CSV는 기존 계약대로 **범위 안의 비제외 행**을 내보낸다. 계산 불가 행도 빈 값·이유를 보존한다. 따라서 CSV 행 수를 그래프 점 수와 억지로 맞추지 않는다. 제외 개수 역시 빈 원으로 그려진 점 수가 아니라 범위 안의 실제 제외 ID 수로 계산한다.

상태 필터를 새 세 가지 의미에 맞춰 정리할 때는 기존 저장본의 `사용/제외` 필터도 처리해야 한다. 예전 ‘사용’은 범위와 무관한 비제외 자료였으므로 조용히 ‘분석 포함’으로 재해석하지 않는다. 이전 필터는 기존 조건으로 읽고 의미가 드러나는 이름을 붙이며, 새 상태 필터를 선택하면 새 정의로 교체한다. 이 과정에서도 확정 ID와 제외 정보는 바꾸지 않는다.

## 6. 구간 선택의 구현 계약

### 6.1 범위 명령과 저장

기존 `applyScope('selection')`은 표 체크 ID를 분석 범위로 쓰는 명령이다. 그래프 손잡이를 움직일 때 체크를 임시로 바꾸어 이 명령을 호출하지 않는다. Workspace에 시간 구간을 직접 받는 명령을 추가하고, 기존 검증·commit·revision·이력·RunStore 저장 경로를 재사용한다.

- 확정된 분석 대상의 기준은 계속 `appliedIds`다. 시간 조건으로 매번 다시 대상을 찾는 방식으로 바꾸지 않는다.
- 손잡이 복원과 구간 표시용으로 시작·끝 시각과 확정 당시 자료 경계를 선택적으로 저장한다. `analysisRange: { startAt, endAt, throughSampleId }`. ID 목록과 반드시 한 작업에서 갱신한다. 새로 들어온 같은 시각 자료도 자동 포함되지 않도록 throughSampleId까지 범위를 검증한다.
- 기존 `appliedScope`의 `all/selection`은 유지할 수 있다. 시간으로 지정한 부분 범위는 `selection`으로 저장하고 메타데이터로 선택 방법을 설명한다. 명시적인 ‘전체 자료’ 확정은 `all`이며 구간 메타데이터를 해제한다.
- 구간 확정은 한 번의 되돌리기 대상이다. 이력에는 ID와 구간 메타데이터를 함께 담는다. 취소·메뉴 이동·손잡이 이동은 이력을 만들지 않는다.
- 기존 `tableLastSampleId`는 불러온 스냅샷의 경계로 유지한다. 화면에서는 ‘표에 불러온 자료’를 ‘분석에 불러온 자료’로 다듬되 내부 이름 변경을 위해 저장 형식을 갈아엎지 않는다.
- 새 자료는 기존처럼 명시적으로 불러온다. 전체 모드는 확장하고, 확정한 부분 범위는 ID를 유지한다. 선택 모드의 ‘전체 구간’으로 모든 자료를 확정한 경우도 현재 시점의 지정 범위이며, 새 자료까지 자동 확장하는 ‘전체 자료’ 명령과 구분해 요약에 표시한다.

### 6.2 시간과 원자료

- 양 끝 시각을 포함한다. 같은 시각의 자료가 여러 개면 모두 포함하고 `sampleId`로 구별한다. 행 순서나 차트 점의 인덱스를 식별자로 쓰지 않는다.
- 한 점만 있는 구간도 살펴볼 수 있다. 0건인 구간의 확정은 막고 바로 이유를 표시한다. 자료 수 부족으로 회귀를 못 하는 것과 구간을 고를 수 없는 것은 구별한다.
- 자정·날짜 변경은 전체 시각으로 비교한다. 기존 표의 날짜 없는 시각 필터를 구간 판정에 그대로 재사용하지 않는다.
- 원자료에 시각 역행이 있으면 시간 구간에 들어오는 자료를 포함하되 수신 순서·원값은 보존하고 선을 끊는다. 첫 기록 기준 음수 경과 시간이 생길 수 있으며 이를 0으로 보정하지 않는다.
- 손잡이를 끄는 동안에는 선택 영역과 개수만 갱신한다. 매 포인터 이동마다 회귀·DB 저장·전체 표 재생성을 실행하지 않는다. 미리 계산한 시각 목록 등을 재사용하고 화면 갱신을 묶는다.
- 5,000행 자료에서도 표 가상화를 유지한다. 그래프 표시 최적화로 점을 줄이더라도 분석·CSV의 원자료 수와 커서의 실제 자료 대응은 바꾸지 않는다.

### 6.3 예전 작업과 파일 호환

이전 작업의 `appliedIds`는 떨어진 여러 행일 수 있다. 최소·최대 시각만 보고 연속 구간으로 바꾸면 학생이 고르지 않은 자료가 분석에 들어간다.

따라서 시간 메타데이터가 없는 기존 지정 범위는 `이전에 지정한 자료 n개`로 표시하고 ID를 유지한다. ‘구간 수정’을 누르면 전체 시간 범위로 새 초안을 제시하며 `새 구간을 확정하면 이전 지정 자료를 대체합니다`를 표시한다. 확정 전에는 예전 결과가 유지된다. 기존 범위를 손잡이 하나로 정확히 표현할 수 있는 것처럼 보이지 않게 한다.

JSON 검증은 새 메타데이터가 없는 파일도 허용하고, 있는 경우 유한한 시각·시작/끝 순서·해당 스냅샷의 ID 대응을 검사한다. 가져온 메타데이터로 ID를 몰래 재작성하지 않는다. 새 필드는 선택적으로 추가하므로 DB 저장소·인덱스 변경이 없다면 DB 버전을 올릴 이유는 없다. 파일 버전 변경 필요 여부는 기존 읽기 호환 검증 후 결정한다.

여기서 구간은 **분석할 시간 범위**다. 이전에 제거한 측정 구간 번호·구간별 기록·구간 저장소를 되살리지 않는다.

공통 범위 판정·시간 경계·포함 ID·메타데이터 검증은 analysis/scope.js, 손잡이·시간 입력·초안은 ui/range-selector.js에 둔다. 새 차트나 저장 엔진을 추가하지 않고 기존 모듈과 연결한다.

Chart.js 인스턴스와 축 좌표 변환은 차트 어댑터 안에 유지한다. 선택 UI에는 시각↔화면 좌표 변환 함수·그릴 영역·사용자 행동 콜백만 제공한다. 드래그 라이브러리·새 차트 라이브러리·범용 상태 관리 도구는 우선 도입하지 않는다.

## 8. 조작과 오류 처리

- 손잡이는 마우스·터치·키보드로 조작할 수 있어야 한다. 접근 가능한 이름과 현재 값을 제공하고, 시간 직접 입력을 대체 수단으로 유지한다. 표 펼침·메뉴 전환 후에도 초점이 사라지지 않게 한다.
- 차트 크기가 바뀌면 손잡이 위치와 선택 영역을 다시 맞춘다. 화면 해제 시 포인터 이벤트·ResizeObserver·차트 자원을 정리하고 측정 세션이나 RunStore를 종료하지 않는다.
- 그래프에서 누른 행이 표 필터에 가려졌다면 필터를 몰래 지우지 않는다. 정보창에 그 사실을 표시하고 학생이 필터를 해제해 찾을 수 있게 한다.
- 값 없는 자료는 자동 제외하지 않는다. 원 자료 표에서 이유를 확인하게 하고 회귀 가능한 자료만 계산에 사용한다.
- 읽기 전용에서는 정보 조회·표 펼침·메뉴 이동과 편집 명령을 구분한다. 기존 잠금·저장 실패 처리를 우회하는 화면 전용 쓰기 경로를 만들지 않는다.
- PNG는 현재 화면의 연장 여부와 요약을 반영한 표시 모델로 출력한다. CSV·JSON은 기존처럼 일관된 스냅샷을 사용한다. 다운로드 창을 연 뒤 새 자료가 들어와도 표시한 행 수와 실제 출력이 달라지지 않게 한다.
- UI의 ‘전체 자료’는 현재 분석에 불러온 자료이고, ‘전체 원자료 CSV’는 실험 전체라는 차이를 유지한다. 아직 불러오지 않은 자료가 있을 때는 두 개수를 구분해 표시한다.

## 9. 구현 순서

| 순서 | 작업 | 이 단계에서 확인할 결과 |
|---|---|---|
| 1 | 범위·제외 공통 판정, 시간 범위 명령, 호환·이력 계약 정리 | 같은 Workspace로 표·그래프·CSV의 포함 여부를 설명할 수 있음 |
| 2 | 분석 화면의 세 메뉴와 원 자료 보기, 기존 시간 차트 연결, 접힌 표·전체 자료 버튼 | 새 CSV나 측정 결과에서 전체 모습이 먼저 보이고 즉시 관계 그래프로 갈 수 있음 |
| 3 | 선택 영역·손잡이·시간 입력·확정·취소·복원 | 끄는 동안 결과가 유지되고 확정 후에만 범위와 회귀가 바뀜 |
| 4 | 관계 그래프의 축 즉시 변경, 표 도킹·계산 진입, 추세선 요약·미리보기 개선 | 표·계산을 열어도 그래프와 설정이 유지됨 |
| 5 | 점 정보·행 강조, 빈 원 제외점, 선택 시 작업 막대·되돌리기 알림 | 점·표·상단 수치·내보내기가 같은 상태를 보여 줌 |
| 6 | 기존 결과를 모은 해석 화면·목적별 저장 버튼, 화면 크기·키보드·재열기 검증 | 세 메뉴가 모두 작동하며 분석 작업과 파일 복원이 이어짐 |

전체 난도는 단순한 버튼 재배치보다 크다. **시간 구간 선택과 기존 저장본 호환이 가장 중요한 신규 작업**이며, 회귀·계산·파일 부분은 기존 기능의 연결과 표시 수정 비중이 높다. 먼저 상태 계약을 고정하면 화면 재배치 과정에서 분석 기준이 갈라지는 것을 막을 수 있다.

대표 확인 시나리오는 다음과 같다.

1. 지원하는 CSV를 열면 표가 접혀 있고 전체 시간 그래프가 먼저 보인다. 구간 선택 없이 관계 그래프로 이동할 수 있다.
2. 1,000개 중 300개를 구간으로 선택하는 동안 기존 결과는 바뀌지 않는다. 확정한 뒤 2개를 제외하면 `분석 포함 298개 · 제외 2개`가 된다.
3. 이 중 현재 축의 유효값이 없는 자료가 3개라면 실제 그래프·회귀는 295개, 분석 CSV는 298행이다. 화면에서 차이의 이유를 확인할 수 있다.
4. 표를 정렬하거나 필터링해도 이 분석 범위·회귀·CSV 행 수는 유지된다. 체크와 점 정보 강조도 서로 바꾸지 않는다.
5. 새 자료 100개를 불러와도 지정한 300개는 유지된다. ‘전체 자료로 관계 보기’를 누르면 1,100개 범위로 바뀌되 제외 2개는 남는다.
6. 구간 수정·계산 열 추가·축 변경·되돌리기·재열기·JSON 복원 뒤에도 원자료 값과 대상 ID가 일치한다.
