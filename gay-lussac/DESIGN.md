이 문서는 화면에서 일어난 행동을 어떤 모듈이 처리하고, 자료와 상태를 어떻게 보존할지 정한다. 기능의 목적·범위·학생 문구와 실시간 점검의 초기 수치는 [기획안](PLAN.md)을 기준으로 한다.

> [!IMPORTANT]
> **화면·통신·실험 기록의 수명을 분리한다.** 안내 화면을 다시 열어도 기록은 이어지고, 연결이 끊겨도 같은 실험이 남는다. 분석은 원자료와 학생의 작업 설정을 구분해 보존한다.

## 1 구현 경계

- 정적 HTML·CSS·JavaScript ES 모듈로 시작한다. 현재 저장소의 실행 방식에 맞춰 `/gay-lussac/`를 독립 진입점으로 두고 해시 경로를 사용한다. 기존 앱의 시작 구조는 [`../js/app.js`](../js/app.js)에서 확인할 수 있다.
- 화면 뼈대부터 최종 앱과 같은 코드를 사용한다. 최초에는 일부 기능을 연결하지 않은 상태로 화면 흐름을 확인하고, M1–M4에서 해당 모듈을 순서대로 채운다.
- 현재 배선 3D·Bluetooth 통신·차트 자원을 필요한 경계에서 재사용한다. 하위 앱은 자체 실험 상태와 저장소를 소유한다.
- 기준 환경은 기획안의 노트북·Chrome/Edge·micro:bit V2 조합이다. 앱 시작 시 연결·저장 기능의 이용 가능 여부를 확인하고 해당 기능 가까이에 안내한다.
- 개발용 자료 재생은 같은 표준 수신 입력을 사용하되 별도 실험 ID와 `source=replay`를 붙인다. 실제 장치 수신과 실기 검증 여부를 구분한다. 저장 파일 가져오기는 검증한 실험 자료를 복원하는 별도 경로다.

## 2 화면과 행동

### 2.1 공통 틀

상단에 **기체의 온도와 압력**, 실험 이름, 연결·수신·저장 상태를 유지한다. 화면 중앙의 주된 내용과 하단의 행동만 준비·측정·분석에 맞춰 바꾼다. 상태 변화로 버튼 위치가 크게 이동하지 않도록 공간을 확보한다.

| 화면 | 넓은 화면의 기본 배치 | 주요 행동과 화면 반응 |
|---|---|---|
| 시작 | 실험 소개와 시작 행동, 저장된 실험 목록 | 처음부터 준비 / 장치가 준비되어 있어요 / 저장된 실험 열기 |
| 준비 | 왼쪽 약 2/3은 3D·전체 그림, 오른쪽은 현재 행동과 확인 | 한 번에 한 연결을 강조한다. 이전 단계와 **↺ 시점 초기화**를 가까이 둔다. |
| 측정 | 상단 온도·압력, 중앙 시간 그래프, 아래 조작 버튼 | 가열 시작·물 추가·장치 변화·측정 마치기를 같은 위치에서 사용한다. |
| 분석 | 도구줄 아래 표와 그래프를 나란히 배치 | 자료 선택 → 원하는 도구 실행. 힌트는 그래프 옆의 접이식 영역에서 연다. |

작은 화면에서는 준비 설명을 모델 아래에 두고, 분석은 **표 / 그래프**를 전환한다. 선택한 행·축·그래프 상태는 유지한다. 실제 폭과 여백은 첫 화면 뼈대에서 확인한다.

### 2.2 화면별 상태

| 상황 | 보여 줄 내용 | 행동 결과 |
|---|---|---|
| 장치 연결 전 | 연결할 장치 그림, 연결 버튼 | 사용자 클릭으로 장치 선택을 연다. |
| 앱 내부 USB 설치 | 지정된 파일명·버전, 연결·전송 진행률, 완료·오류 | 공식 API가 완료된 뒤 **수신 확인하기**로 실제 수신을 확인한다. |
| 최초 수신 확인 | 새 온도·압력, 마지막 수신 시각 | 기록은 이미 준비 구간으로 시작된다. 배터리 전환과 용기 배치를 이어 안내한다. |
| 가열 전 | 준비 구간 그래프, **가열 시작** | 버튼을 누른 시각을 사건으로 남긴다. |
| 가열 중 | 같은 그래프와 조작 버튼, 필요한 점검 안내 | 물 추가·장치 변화는 측정을 계속하면서 기록한다. |
| 수신 중단 | 마지막 값과 시각, **다시 연결** | 오래된 숫자를 흐리게 표시하고 시간 그래프를 구간 경계에서 끊는다. |
| 저장 문제 | 미저장 자료 수, **다시 저장 / 파일로 보관** | 수신 자료를 메모리에 유지하고 저장을 재시도한다. |
| 분석 첫 진입 | 원자료 표, 자료와 축을 고르는 짧은 안내 | 학생이 그래프를 만든다. 힌트는 처음부터 닫아 둔다. |
| 분석 자료 부족 | 필요한 자료나 축을 안내 | 사용할 수 있는 다른 도구는 계속 사용할 수 있다. |

준비 단계 바는 클릭·키보드로 원하는 단계에 바로 이동하는 버튼으로 사용한다. 배선은 첫 연결 단계로 이동하고, 각 연결은 기존 이전·다음 버튼으로 살펴본다. 단계 이동은 연결·수신 확인 상태를 초기화하거나 완료로 처리하지 않는다. 프로그램 준비·USB 설치 작업 중에는 기존 이전·다음과 함께 단계 바도 잠시 비활성화한다. 분석 도구는 독립적으로 열리며, 힌트를 읽은 횟수나 답변 여부에 연결하지 않는다. 버튼·표 선택은 키보드로도 조작하고 상태는 글자로 함께 전달한다.

## 3 상태 전환

### 3.1 따로 관리할 상태

| 상태 | 값 | 소유자 |
|---|---|---|
| 화면 | `home / prepare / measure / analysis` | 앱 제어기 |
| 실행 중 기록 | `idle / collecting / paused / finishing / ended` | 측정 세션 |
| Bluetooth | `disconnected / connecting / connected` | 통신 어댑터 |
| USB 설치 | `idle / loading / ready / connecting / flashing / success / cancelled / error / unavailable` | 프로그램 전송 어댑터 |
| 유효값 수신 | `waiting / receiving / stale` | 규칙이 계산하고 측정 세션이 상태 보관 |
| 저장 | `clean / pending / saving / error` | 열린 실험의 RunStore |
| 저장된 실험 | `open / paused / complete / interrupted` | RunStore가 변경을 관리하는 `Run` 레코드 |

예를 들어 `Bluetooth=connected`, `수신=stale`, `저장=clean`이 동시에 가능하다. 화면에는 **장치는 연결되어 있지만 새 값이 들어오지 않음**, **지금까지의 자료는 저장됨**을 각각 표현한다.

### 3.2 전환 규칙

| 행동·사건 | 처리 |
|---|---|
| 새 실험 준비 | 실험 ID를 만들고 작성 권한을 확보한다. 준비 단계와 프로그램 후보 정보를 저장한다. |
| 최초 유효값 | 준비 구간부터 `collecting`으로 기록한다. 앞서 수신한 형식 오류는 오류 사건으로 남길 수 있다. |
| 안내 다시 보기 | 화면만 바꾼다. 세션·수신 콜백·저장 대기열을 유지한다. |
| 가열 시작 | `heating-start`를 한 번 기록한다. 버튼 중복 입력으로 사건을 복제하지 않는다. |
| 연결 해제 | 통신 자원을 정리하고 구간 종료를 기록한다. 기록 세션은 이어 연결할 수 있는 상태로 유지한다. |
| 같은 실험에 다시 연결 | 마지막 샘플 ID 다음부터 새 구간으로 기록한다. 재연결을 새 실험으로 처리하지 않는다. |
| 기록 일시정지 | `paused`로 바꾸고 현재 구간·정지 사건을 저장한다. 연결·현재 값은 유지하되 새 수치와 형식 오류를 원자료·사건에 추가하지 않는다. 물 추가·장치 변화의 사용자 메모는 기록할 수 있다. |
| 기록 재개 | 정지 전 자료를 유지하고 새 유효값부터 새 구간을 시작한다. 정지 중 표시값을 소급 저장하지 않는다. |
| 측정 마치기 | 입력을 먼저 마감해 `finishing`으로 바꾸고 종료 사건·남은 자료·완료 상태를 저장한다. 성공 또는 임시 분석 선택 후 `ended`로 이동한다. |
| 기록 중 분석 경로 진입 | 진입 시 자료 복사본을 표에 표시한다. 기록은 유지하고 추가 자료 건수와 **새 자료 적용**을 제공한다. 화면 이동만으로 정지·종료하지 않는다. |
| 새로고침 후 미완료 기록 열기 | 저장된 부분을 보여 주고 **이어 측정 / 여기까지 분석**을 제공한다. 잠금 확보 후 중단 상태를 기록한다. |
| 일시정지된 실험 다시 열기 | 작성 권한이 있으면 `paused` 세션을 복원한다. 연결해도 미리보기만 제공하며 **기록 재개**를 눌러야 기록한다. |
| 완료된 실험 다시 열기 | **측정 완료**와 **추가 측정**을 표시한다. 작성 권한과 기존 자료의 저장 완료를 확인하고, 체크리스트 제출 뒤 같은 실험을 `open`으로 바꾼다. |

기록 중 다른 실험을 열거나 새 실험으로 바꾸려면 먼저 현재 측정을 마친다. 미저장 자료가 있는 경우 해당 RunStore를 유지하거나 저장·내보내기를 처리한 뒤 바꾼다. 앱 제어기는 화면을 교체하면서 세션이나 RunStore를 폐기하지 않는다.

## 4 모듈 경계

### 4.1 자료 흐름

```mermaid
flowchart TD
    B["표준 수신 입력"] --> S["측정 세션"]
    S --> Q["RunStore"]
    S --> C["순수 점검 규칙"]
    S --> V["측정 화면"]
    C -->|"상태와 근거"| S
    Q <-->|"읽기와 저장 묶음"| D["Repository"]
    Q -->|"일관된 자료 조회"| A["분석 작업 공간"]
    A -->|"작업 복사본"| Q
    A --> W["표와 그래프 화면"]
```

**RunStore**는 열린 실험의 자료·저장 상태를 관리하는 단일 창구이고, **Repository**는 실제 IndexedDB 접근을 맡는다. 저장된 자료와 미저장 자료의 병합은 RunStore만 수행한다. 앱 제어기는 모듈을 연결하고 종료·화면 전환 순서를 조율한다.

### 4.2 최소 모듈 계약

아래 함수 이름은 구현 시작점이다. 같은 책임을 유지하는 범위에서 파일 내부의 작은 함수를 나눌 수 있다. 전역 이벤트 시스템이나 플러그인 등록 체계는 초기 구조에 필요하지 않다.

| 위치·모듈 | 주요 계약 | 소유하는 상태 |
|---|---|---|
| `app.js` | `openRun(id)`, `navigate(screen)`, `finishAndAnalyze()` | 현재 화면, 세션·RunStore·화면의 참조와 호출 순서 |
| `guide/steps.js`, `guide/viewer-adapter.js` | `getStep(id)`, `applyStep(step)`, `restoreStep()` | 안내 단계와 모델 표시 상태 |
| `measurement/transport.js` | `connect(profile, onInput, onState)`, `disconnect()` | 장치, 연결 시도 번호, 시작 명령 재시도와 수신 정리 |
| `measurement/decoder.js` | `decode(line, profile)` | 내부 상태 없이 수치·필드별 유효성 또는 형식 오류 반환 |
| `measurement/session.js` | `acceptInput(input)`, `markEvent(type, payload)`, `pause()`, `resume()`, `startAdditional()`, `finish()` | 샘플 번호, 구간·시간 기준, 기록 정지·재개·입력 마감, 규칙별 상태·평가 일정 |
| `diagnostics/` | `step(previousState, input, now, config)` | 숨은 상태 없이 `nextState`와 관측 결과 반환 |
| `data/run-store.js` | `appendSample()`, `appendEvent()`, `saveWorkspace()`, `correctEvent()`, `flush()`, `getSnapshot()` | 열린 Run, 사건 ID 할당, 미저장 복사본, 저장 상태·일정·작성 잠금 |
| `data/repository.js` | `open()`, `readRun()`, `readSamples()`, `readEvents()`, `readWorkspace()`, `commitBatch()` | DB 연결·스키마·인덱스·트랜잭션 |
| `analysis/workspace.js` | `applySelection()`, `updateColumn()`, `setExcluded()`, `fitLine()`, `undo()` | 표 상태, 적용 자료, 계산·그래프 설정, 작업·계산 입력 revision |
| `analysis/calculations.js` | `evaluateColumns()`, `linearFit()` | 입력에서 계산한 결과. DOM·장치·DB에 의존하지 않음 |
| `data/files.js` | CSV·JSON 읽기/쓰기 | 형식 변환과 실험 스키마 검증 |
| `ui/table-view.js`, `ui/chart-view.js` | `render(model)`, `dispose()`; 차트의 `exportPng()` | DOM·canvas·라이브러리 인스턴스 |

공통 레코드와 입력 계약은 `data/contracts.js`의 JSDoc·검증 함수로 시작한다. 의존 방향과 외부 도구 경계는 [구현 원칙 §3](ARCHITECTURE.md#3-의존-방향과-외부-도구의-경계)을 따른다. 화면은 사용자 행동을 전달하고 결과를 표시하며, 저장과 점검은 화면의 단계 번호를 입력 조건으로 사용하지 않는다. PNG의 실제 다운로드 요청은 작은 `ui/download.js`가 처리한다.

RunStore의 생성·열기는 저장된 상태를 읽고 작성 권한을 확보한다. 메타데이터 변경은 `updateRun(patch)`로 전달해 revision을 갱신하며, `close()`는 저장·미저장 자료 처리를 마친 뒤 잠금과 저장 일정을 해제한다.

## 5 3D 안내와 장치 연결

### 5.1 기존 3D의 최소 통합

[`../bmp280-wiring/index.html`](../bmp280-wiring/index.html)을 같은 출처의 iframe으로 한 번 생성해 유지한다. 구현 시 기존 페이지에 `embed=1` 표시 모드와 작은 `embed-bridge.js`를 추가한다. 이 파일은 기존 번들 바깥에서 정해진 UI 연결 지점만 호출한다.

| 기존 연결 지점 | 적용 방법 |
|---|---|
| `[data-view]`의 `iso/front/back/top/ports` | 준비 단계별 기본 시점을 적용한다. |
| `[data-wire]`의 `vcc/gnd/scl/sda` | 해당 선만 강조한다. 기존 동작은 토글이므로 이미 선택된 선을 다시 눌러 해제하지 않도록 현재 상태를 확인한다. |
| `#all-wires`, `#explode` | 전체 선 표시와 분리 정도를 명시적인 값으로 적용한다. |
| `#inspect-connectors` | 단자 확대와 분리값 변경이 함께 일어나는 동작으로 취급한다. |
| `#reset` | 전체 초기화에 사용한다. **↺ 시점 초기화**는 현재 단계의 시점·강조·분리값을 다시 적용한다. |

임베드 모드는 기존 제목·사이드바의 표시만 조정하고 필요한 DOM은 유지한다. 프레임과 3D 영역의 높이를 정해 모델을 크게 표시한다. 일반 주소의 독립 안내도 계속 사용할 수 있도록 변경 범위를 한정한다.

<details>
<summary><strong>새로 추가할 프레임 메시지 계약</strong></summary>

- 메시지는 `channel: "gay-lussac-guide"`, `version: 1`, `type`, `requestId`를 갖는다.
- 부모의 준비 요청에 프레임은 `ready`를 응답한다. 단계 적용은 `apply-state`와 `{view, wire, explosion}`만 허용하고 `applied` 또는 `error`로 응답한다.

- `wire`는 `null/vcc/gnd/scl/sda`를 허용한다. `null`은 **전체 배선 표시·강조 없음**이며 `#all-wires`에 대응한다. 특정 선은 전체 표시 상태에서 해당 선을 선택한다. `explosion`은 기존 모델 범위인 0–60으로 제한한다.
- 양쪽은 발신 출처와 상대 창을 확인한다. 임의 선택자·함수명·스크립트를 메시지로 받지 않는다. 부모는 마지막 요청과 다른 응답을 현재 단계 완료로 처리하지 않는다.
- 표시 적용 완료는 실제 배선 완료를 뜻하지 않는다. 실제 조작은 사용자가 확인한다.
- 자유 회전 뒤 **↺ 시점 초기화**는 동일한 `apply-state`를 다시 보낸다. 프레임 통신·WebGL 이용이 어려우면 같은 단계의 정지 그림·연결표를 제공한다.

현재 모델의 `ports` 시점은 USB·전지 단자를 함께 보여 준다. 개별 포트 확대, 배선 양끝에 맞춘 카메라 이동, 부드러운 전환은 필요한 부분부터 추가할 작업이다. 현재 코드에 외부 제어 API가 이미 있다고 가정하지 않는다. 용기·수조·고정 장치 안내는 기획안대로 별도 전체 그림으로 보완한다.

시작 화면과 마지막 용기 배치 단계는 같은 `assets/setup.svg`를 재사용한다. micro:bit·확장 보드와 배터리는 밀폐 용기 바닥에, 센서는 중간 높이의 공기 중에 두고 모든 배선을 내부에 그린다. 뚜껑을 통과하는 USB·센서 선 없이 Bluetooth 무선 전송을 표시한다. 물과 고정 장치는 용기 외부에만 표시한다. 이 그림은 [참고 장치 기록](https://github.com/Cho-WH/Gay-Lussac/blob/main/experiments/pressure-temperature/runs/20260822-01.md)과 후속 고정 계획을 반영한 배치 개념도이며 제품의 정확한 치수·배터리 수량을 지정하는 도면은 아니다.

그림의 표기는 부품 이름과 ‘유리 밀폐 용기’로 간소화한다. 아래에는 ‘센서는 벽에 닿지 않고 최대한 용기 중앙에 떠 있도록 하세요.’만 안내하고 가느다란 화살표로 센서를 가리킨다. 그림 밖에 같은 배치 설명을 캡션으로 반복하지 않는다.

준비 그림의 도구는 상단에 모은다. 준비물·배선 단계에는 **3D 보기 / 배선표 보기**를 제공하고, **↺ 시점 초기화**는 3D 표시 중에만 보인다. **크게 보기**는 기존 독립 배선 안내를 연다. 하단 도구 영역과 회전·확대 힌트는 두지 않는다. 용기 배치에서는 도구를 숨기되 도구·그림의 공간은 유지한다. 배선표는 역할·확장 보드·BMP280의 네 연결 행으로 구성하며 현재 행을 색상과 글자로 표시한다. 보기 전환과 현재 행 변경에도 그림 영역·행 높이는 유지한다. 3D 표시 실패 시 배선표와 실패 안내를 제공한다.

불러오기 상태는 그림 안에 절대 배치하여 별도 줄을 만들지 않는다. 안내 영역에는 내부 스크롤을 만들지 않는다. `ui/guide-view.js`가 실제 화면과 같은 텍스트 렌더링 함수로 배선 설명의 비활성·비노출 측정 요소를 만들고, `ui/guide-layout.js`가 현재 폭에서 네 단계의 자연 높이를 측정한다. 설치·수신 조작 영역은 복제하지 않는다. 가장 큰 값을 배선 단계의 공통 최소 높이로 확보하며 다른 단계는 각 내용 바로 아래에 완료 버튼을 둔다. 폭·글꼴 변경 시 재측정하며 수신·로딩 갱신마다 높이를 바꾸지 않는다. 예상보다 긴 오류는 잘라 숨기지 않고 자연스럽게 펼친다. 배선표도 자연 높이에 맞춰 그림 영역의 최소 높이를 확보한다. 좁은 화면에서는 도구 모음 두 줄의 공간을 미리 확보한다. 프로그램 전송 진행률·수신 확인 문구·배선표의 현재 단계 표시도 공간을 확보한다.

단계 바는 하나의 선택 밑줄이 현재 단계로 300ms 동안 미끄러지듯 이동한다. 오른쪽 설명은 이동 방향에 따라 20px 옆에서 제자리로 들어오는 300ms 슬라이드와 약한 투명도 전환을 적용한다. 모델·그림에는 페이드를 적용하지 않고 완료 버튼은 전환 효과에서 제외한다. 같은 단계의 수신 갱신에는 효과를 반복하지 않고 빠르게 이동하면 이전 효과를 취소한다. `prefers-reduced-motion: reduce`에서는 두 전환 효과를 생략한다.

### 5.2 공식 전송과 실제 수신

기획안의 [공식 USB 전송 경로](PLAN.md#3-3d-장치-준비와-공식-usb-전송)를 그대로 사용한다. `program-config.js` 한 곳에서 HEX 경로·표시 이름·버전·해시·센서 프로파일·검증 상태를 관리한다. 현재 HEX는 실제 V2에서 설치·온도/압력 수신·배터리 동작을 확인한 `communication-verified` 상태다. 검증한 환경과 한계는 README에 기록하며 센서 정확도 검증과 구분한다.

`guide/programmer-adapter.js`가 공식 라이브러리의 USB 객체·준비한 HEX·전송 상태를 소유한다. 프로그램 단계에 들어오면 파일을 읽어 SHA-256과 V2용 HEX를 확인한다. 준비가 끝난 설치 버튼에서 다른 비동기 작업을 기다리기 전에 공식 `connect()`를 호출한다. 최초 장치 선택은 브라우저 권한 흐름을 따른다. V2 확인 후 앱이 제공한 `beforeFlash`에서 BLE를 해제하고 `flash(source, { partial: false, progress })`로 전체 전송한다. `flash()`가 성공으로 끝나야 완료 상태가 되며 진행률 100%는 완료 근거가 아니다. 취소·실패 모두 USB 점유를 해제하고 중복 설치를 막는다. 공식 객체는 어댑터 밖으로 내보내지 않는다.

설치 중에는 Bluetooth 연결과 이전·다음 단계 버튼을 막고, 다른 화면에서도 설치 진행 안내를 유지한다. 화면 전환은 전송 객체를 해제하지 않는다. 새로고침·닫기는 브라우저 확인을 요청하며 문서를 떠날 때 정리한다. 같은 페이지에서 선택한 장치를 기억하지만 새 페이지에서는 다시 선택한다. 앱은 전송 성공과 별도로 **새로운 유효값 3개가 1초 이상에 걸쳐 수신됨**을 확인하고, 배터리 전환 후 그 시점 이후의 값으로 다시 확인한다.

`transport.js`는 기존 [`../js/bluetooth.js`](../js/bluetooth.js)의 장치 선택·연결·알림·`bme` 명령·정리를 감싼다. 기존 연결 화면에 있는 첫 값 대기와 제한된 시작 명령 재시도는 세션과 분리해 옮긴다. 현재 기준인 첫 값 대기 3초, 명령 간격 300ms·최대 5회를 연결 설정으로 관리하고 M1 실기에서 적합성을 확인한다. [기존 연결 구현](../js/ui/connection-panel.js)

어댑터는 decoder의 결과를 `reading / parse-error` 입력으로 내보내고, 연결 시도 ID·UTC 수신 시각·단조 시각을 함께 전달한다. 파싱 가능한 범위 밖 수치도 `reading`에 남긴다. 시작 명령 재시도는 프로파일상 유효한 첫 Reading을 받으면 종료하며, 안내의 3개·1초 확인과 구분한다.

연결 시도 번호가 지난 응답·콜백·재시도를 무시하고, 종료 시 타이머와 알림을 정리한다. 연결 객체는 통신 어댑터가 소유하며 기존 전역 `state.history`나 연결 UI의 초기화 함수를 새 기록의 저장소로 사용하지 않는다.

## 6 데이터와 저장 계약

### 6.1 표준 데이터

| 레코드 | 필수 내용 | 규칙 |
|---|---|---|
| `Run` | `id`, 스키마 버전, `runRevision`, 이름, 생성·갱신 시각, 상태, 프로그램·프로파일, 자료 출처, 구간 정보, 마지막 저장 샘플 ID | 초보자·후속 중급자 모두 같은 구조 사용 |
| `Sample` | `runId`, `sampleId`, `segmentId`, `receivedAt`, `segmentElapsedMs`, `temperatureC`, `pressureHpa`, `validity` | 샘플 ID는 실험 내 증가 정수. 원값은 추가 저장 |
| `Event` | `runId`, `eventId`, UTC 시각, `segmentId`, `segmentElapsedMs`, 종류, 내용, `source=user/system` | 가열·배치·장치 조작·수신 변화·점검·종료·정정을 구분 |
| `Workspace` | `runId`, `workspaceRevision`, `analysisInputRevision`, 표 상태, 현재 선택 ID, 적용 후보 ID, 제외 사유, 계산 열, 축·회귀·메모 | 원자료와 별도로 자동 저장 |

RunStore가 실험 ID와 실험 내 증가하는 사건 ID를 할당한다. 세션은 전달받은 실험 ID와 마지막 샘플 ID를 사용해 샘플·구간을 이어간다. `markEvent()`는 사건 내용을 만들고 RunStore의 `appendEvent()`로 확정된 ID를 받는다. 수정 가능한 레코드의 revision은 변경할 때마다 증가하며 스키마 버전과 구분한다.

`receivedAt`은 UTC 기준 Unix 밀리초이며 CSV에서는 ISO 시각으로 출력한다. 센서 내부의 정확한 측정 시각으로 부르지 않는다. `segmentElapsedMs`는 같은 실행 구간의 단조 경과시간으로, 점검창과 수신 지속시간을 재생할 때 사용한다. 단조 시계와 실제 UTC 시각의 차이는 [MDN의 시간 API 설명](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)을 따른다.

측정 중 사건에도 해당 구간 ID와 구간 경과시간을 함께 남겨 점검창에 대응시킨다. 아직 구간이 없는 준비 사건이나 구간 사이의 사건은 두 값을 `null`로 두고 UTC 시각과 발생 순서를 보존한다. 실험의 구간 정보에는 시간의 출처를 `monotonic / utc-derived`로 구분한다.

수신 파서는 프로파일이 정한 필드 수와 숫자 전체를 검사한다. 현재 3필드 파서의 `parseFloat`만으로 형식 검사를 끝내지 않는다. 파싱 가능한 범위 밖 원값은 필드별 `validity`와 함께 보존하고, 파싱 불가능한 수신은 시각·오류 종류를 남긴다. 유효 구간이 시작되기 전의 수치도 보존하며 이때 구간 ID·경과시간은 `null`로 둔다. BMP280 프로파일에서 측정하지 않는 습도는 유효한 센서값으로 노출하지 않는다. [기존 파서](../js/utils/parseSample.js)

### 6.2 연속 구간

재연결, 새로고침 뒤 측정 재개, 유효값 장기 공백, 시각 역행, 브라우저 정지·재개로 연속성을 확인할 수 없는 때에는 다음 유효값부터 새 `segmentId`를 부여한다. UTC 시각과 단조 시계의 차이가 크게 달라진 경우도 시각 불연속 사건으로 남긴다.

최근 60초 표시는 실제 수신 경과시간으로 계산한다. 전체 시간 그래프는 UTC 수신 시각에 따른 경과시간을 표시하되 구간 사이의 선을 끊는다. 시각이 변경된 구간은 표시하고, 공백을 보간하거나 0으로 채우지 않는다. 점검창은 같은 연속 구간 안에서만 구성한다.

### 6.3 IndexedDB와 저장 대기열

DB 이름 `bme280.gay-lussac`, 버전 `1`, 저장소 `runs / samples / events / workspaces`를 사용한다. `samples` 키는 `[runId, sampleId]`, `events` 키는 `[runId, eventId]`, 작업 공간 키는 `runId`로 둔다. 샘플은 실험·구간별로 읽을 수 있게 인덱스를 둔다.

1. 세션이 만든 샘플을 RunStore에 전달한다. RunStore가 원자료·사건·메타데이터·작업 복사본의 대기열을 소유한다. 화면용 최근 자료는 별도의 읽기용 캐시다.
2. RunStore는 정상 동작 시 최대 약 1초 주기로 대기 묶음을 저장 요청하고 한 실험의 쓰기를 직렬화한다. 저장할 묶음의 ID와 revision을 요청 전에 고정한다.
3. Repository의 `commitBatch()`는 해당 묶음의 샘플·사건·실험 메타데이터와 필요한 작업 변경을 같은 트랜잭션으로 기록한다.
4. 트랜잭션 완료 응답에는 확인된 샘플·사건 ID와 Run·Workspace revision을 담는다. RunStore는 **응답된 ID·revision까지만** 확정한다. 그동안 새로 들어온 자료·수정은 다음 묶음에 남긴다.
5. 실패하면 같은 ID로 재시도한다. 이미 저장된 자료와 충돌할 경우 내용을 확인하고 원자료를 덮어쓰지 않는다.

예를 들어 작업 revision 1을 저장하는 동안 2로 수정하면, 1의 저장 성공 뒤에도 2가 미저장 상태로 남는다. Workspace의 변경 복사본은 변경 처리 안에서 즉시 RunStore에 전달하고, DB 쓰기만 묶어서 지연한다. `flush()`는 호출 시점의 ID·revision까지 저장 완료를 기다린다.

`clean`은 대기 자료와 작업 변경이 모두 확정된 상태다. 요청 하나의 성공과 전체 트랜잭션 완료를 구분하고, DB 작업 중 네트워크·UI 응답을 기다리지 않는다. Repository 내부는 idb를 사용하며 완료는 `tx.done`으로 확인한다. [IndexedDB 문서](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB), [라이브러리 선택](ARCHITECTURE.md#5-초기-라이브러리-선택)

### 6.4 측정 종료와 임시 분석

**측정 마치기**는 세션의 입력과 진단 평가를 닫고 종료 시점의 자료를 고정한다. 앱은 RunStore에 종료 저장을 요청한다. 종료 사건과 남은 자료, `Run.status=complete`를 같은 트랜잭션으로 저장한 뒤 분석을 연다. 중복 클릭은 같은 종료 요청으로 처리한다.

**기록 일시정지**는 종료와 별개다. 입력을 먼저 `paused`로 전환하고 `recording-paused` 사건·구간 종료·정지 상태를 저장한다. 저장 실패해도 기록은 정지된 상태를 유지하며 재저장할 수 있다. 연결 어댑터는 계속 동작하고 관찰자는 현재 값·수신 상태만 갱신한다. 정지 중 값은 그래프 캐시·RunStore·CSV에 들어가지 않는다. **기록 재개**에서 `recording-resumed`를 남기고 연속성 확인을 새로 시작한다. 정지 중 새로고침해도 저장된 `paused` 상태를 유지한다.

**추가 측정**은 종료된 실험의 상단 공통 행동이다. 팝업에서 용기·기체 부피, 밀폐·뚜껑 개방, 센서·배선·설정의 세 조건에 각각 **변경 없음 / 변경됨 / 확실하지 않음**을 선택한다. 변경·불확실 항목이 있으면 메모를 요구하고 새 실험 분리를 권하되, 조건 변화 탐구를 위해 같은 실험에 추가할 수 있다. 취소하면 상태와 기록을 바꾸지 않는다. 확인 결과·메모·기존 마지막 샘플 ID는 `additional-measurement` 사건으로 보존한다. 기존 자료·Workspace는 그대로 두고 샘플·구간 ID를 이어간다. 용기 배치와 가열 시작 확인은 새로 받으며 Bluetooth 연결은 별도 사용자 행동이다. 연결 단절 구간과 조건 변화 기록은 서로 다른 의미로 유지한다.

실패하면 **저장 다시 시도 / 임시 자료로 분석**을 제공한다. RunStore의 `getSnapshot()`은 최신 Run·샘플·사건·Workspace를 한 시점에 복사한다. M2에서는 처음 열 때 한 읽기 트랜잭션으로 전체 자료를 가져와 RunStore에 보유하고 확정 ID·revision으로 미저장 자료를 구분한다. 저장 뒤에도 원자료를 보유하므로 DB 재조회나 별도 병합 없이 실패 시 CSV를 만들 수 있다. 저장 완료·나중 입력은 이미 만든 스냅샷을 바꾸지 않는다. 메모리 사용은 열린 실험 크기에 비례한다.

분석과 CSV·JSON 내보내기는 같은 스냅샷 계약을 사용한다. 앱은 화면 전환 동안 같은 RunStore 참조를 유지하며, 자체 버퍼나 별도 병합 로직을 만들지 않는다.

임시 분석에는 **미저장 자료가 있음**과 대기 건수를 표시하고, 분석 작업 변경도 미저장으로 관리한다. 메모리 자료의 저장이 끝나면 같은 실험을 저장된 상태로 전환한다. 새로고침 복원은 마지막 완료 트랜잭션까지이며, 새로 열린 앱은 미완료 저장분이 복원되었다고 표시하지 않는다.

### 6.5 한 실험의 작성 권한

RunStore는 `bme280.gay-lussac:run:<id>` 이름의 Web Lock 수명을 관리한다. 잠금을 잡은 탭만 해당 실험을 측정·수정한다. 잠금은 측정에서 분석으로 넘어가도 유지하고, 실험을 닫을 때 해제한다. 같은 출처의 이름별 잠금 동작은 [Web Locks 문서](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)에 근거한다.

두 번째 탭은 `ifAvailable` 방식으로 잠금 실패를 확인한 뒤 읽기 상태로 연다. 원자료 보기와 내보내기를 제공하고 미완료 상태·분석 작업을 덮어쓰지 않는다. 작성 권한 재시도는 사용자 행동으로 수행한다. 임시 자료만 남은 실험은 버퍼를 보유한 탭에서 계속 다룬다.

### 6.6 조작 기록의 정정

사건 시각·메모 정정은 RunStore의 `correctEvent(eventId, patch)`를 통해 검증한다. 원래 사건을 덮어쓰지 않고 `event-correction` 사건에 대상 ID, 정정 revision, 변경 전후 값과 정정 시각을 남긴다. 사용자 관찰 사건의 시각·내용을 수정할 수 있으며 자동 수신·진단 기록은 원래 근거로 보존한다.

현재 관찰 표시는 최신 정정을 적용한다. 사건 발생 시각과 정정 시각을 구분하며, 당시 진단 계산을 소급 변경하지 않는다. 정정을 위해 종료된 측정 세션을 다시 실행하지 않는다. JSON 내보내기는 원래 사건과 정정 기록을 함께 담는다.

## 7 학생 주도 분석의 동작 계약

### 7.1 표 상태와 적용 자료

원자료 표는 페이지 버튼 없이 연속 스크롤로 이동한다. 고정 높이 행과 위·아래 여백으로 전체 스크롤 길이를 유지하며, 보이는 행과 주변 8행만 DOM에 표시한다. 머리글은 고정하고 키보드 Page Up/Down·Home/End로도 이동한다. 전체 자료는 RunStore가 보유하며 이 최적화는 DB를 나누어 읽는 방식이 아니라 표시 행 수를 제한하는 방식이다. 원자료·CSV 범위는 바뀌지 않는다.

M2의 분석 표는 첫 진입 또는 **새 자료 적용** 시점의 복사본을 사용한다. 이후 수신은 전체 기록·CSV에만 추가하며 표의 적용 범위를 자동으로 늘리지 않는다. 이 임시 보기 범위는 현재 탭 안에서 유지한다. M3에서는 적용 후보 ID·계산·그래프·회귀를 Workspace로 저장·복원하고 추가 측정만으로 기존 입력 범위를 바꾸지 않는다. 새 자료를 명시적으로 적용하면 입력 revision을 갱신하고 재계산을 요구한다.

| 집합·상태 | 의미 | 바뀌는 행동 |
|---|---|---|
| 표 보기 | 정렬·필터·스크롤 위치 | 표 조작 |
| 현재 선택 ID | 지금 체크하거나 범위 선택한 행 | 클릭·범위 선택·전체 선택 |
| 적용 후보 ID | 그래프·계산에 적용한 자료 범위 | **선택 자료 적용**, **전체 자료 적용** |
| 제외 ID와 사유 | 후보 중 분석에서 제외한 행 | 분석에서 제외·복원 |
| 실제 유효점 | 후보에서 제외 행을 뺀 뒤 필요한 열 값이 유효한 점 | 자료·축·계산 열이 바뀔 때 계산 |

표의 행 번호와 샘플 ID를 분리한다. 선택은 정렬·필터·스크롤 이동 뒤에도 ID로 유지한다. **전체 선택**은 현재 필터에 해당하는 전체 행을 뜻하며 건수를 표시한다. 숨겨진 선택 행이 있으면 선택 수와 현재 표에 보이는 선택 수를 함께 보여 준다.

자료를 제외해도 적용 후보 ID를 지우지 않는다. 복원하면 같은 범위로 돌아온다. 그래프에는 후보 수·사용 점 수·제외 수·값 부족 수를 구분해 표시한다. 필드 유효성에 문제가 있는 행은 표에서 확인할 수 있으며 필요한 값이 유효한 계산에만 사용한다.

### 7.2 계산 열과 그래프

계산 열 정의는 `id`, `name`, `unit`, `lhs`, `op`, `rhs`로 둔다. 입력은 열 ID 또는 상수, 연산은 `+ / − / × / ÷`이다. **절대온도**와 **압력/절대온도**는 이 정의를 만들어 주는 프리셋으로 구현한다.

계산 열이 다른 계산 열을 참조할 수 있도록 하되 참조가 한 방향으로 이어지는지 확인한다. 순환 참조·삭제된 입력·분모 0·유효하지 않은 숫자는 이유가 있는 빈 결과로 처리한다. 입력·출력 단위를 보여 주며 임의 코드를 실행하는 수식 처리는 사용하지 않는다.

그래프 만들기는 적용할 자료와 X·Y축을 확정한다. 산점도가 기본이고 시간축에서는 구간별 시간 변화선을 선택할 수 있다. 회귀는 현재 그래프의 동일한 실제 유효점을 사용한다. 표시를 위해 점을 줄여 그리는 경우에도 계산·내보내기의 원자료 범위는 유지한다.

### 7.3 회귀 결과와 변경 처리

`linearFit()`은 사용 점 수, 회귀식 계수, R², x절편의 상태와 이유를 따로 반환한다. 서로 다른 X값이 2개 이상 필요하며, 기울기 0의 회귀선과 y절편도 유효할 수 있다. Y가 일정하면 R²의 계산 불가 이유를 표시한다.

x절편 `−b/a`는 기울기 0·비유한 결과·수치적으로 불안정한 나눗셈에서 보류한다. 수치 오차 허용값은 축의 크기에 맞춰 계산 엔진에 두고 검증 자료로 확인한다. 작은 기울기라는 이유로 원래 회귀선까지 없애지 않는다. 절대영도 표시는 섭씨온도 X축·압력 Y축일 때 학생이 직선 연장을 선택해 연다. 측정 범위와 연장선을 구분하며 R²로 실험 성공을 판정하지 않는다.

| 변경 | 그래프·회귀의 처리 |
|---|---|
| 정렬·필터·현재 행 선택·메모 | 기존 적용 자료와 회귀 유지 |
| 새 범위 적용·제외/복원·계산 열 수정·축 변경 | 그래프 갱신, 회귀·외삽은 **다시 계산 필요** |
| 직선 맞추기 | 현재 입력 버전에 대한 회귀 저장 |
| 되돌리기·다시 실행 | 작업 정의 복원. 계산 입력이 바뀌면 회귀 상태도 갱신 |

Workspace는 저장할 변경마다 `workspaceRevision`을 증가시키고, 계산 대상·식·축이 바뀔 때만 `analysisInputRevision`도 증가시킨다. 회귀에는 사용한 입력 revision을 함께 저장한다. 버전이 다른 결과나 늦게 도착한 계산 결과를 현재 그래프의 결과로 표시하지 않는다. 정렬·필터·메모만 바꾸어도 저장은 필요하지만 기존 회귀는 유지된다.

되돌리기는 작업 정의를 복원하되 revision 번호를 뒤로 돌리지 않는다. 되돌리기 이력은 현재 세션에서 유지하고, 재접속 시에는 저장된 현재 작업 상태를 복원한다.

## 8 실시간 점검의 연결

수신 점검과 압력 반응 점검은 별도 함수·설정으로 둔다. 공개 계약은 `step(previousState, input, now, config) → { nextState, observation }`이다. 입력은 표준 샘플·형식 오류·연속 구간·배치/가열/장치 사건·평가 tick이며, 관측 결과는 `ruleId`, `ruleVersion`, `state`, `reasonCode`, `evidence`이다. UI 문구는 `reasonCode`에 대응하는 문구표에서 가져온다.

규칙 내부에서 현재 시각·DOM·DB를 직접 읽거나 타이머를 만들지 않는다. 측정 세션이 규칙별 상태, 주입된 단조 시계와 평가 일정을 소유한다. 새 수신이 없어도 tick으로 중단을 평가하고, 측정 종료 시 평가를 정리한다.

| 규칙 | 상태와 입력 처리 |
|---|---|
| 수신 | 최초 대기, 수신 중, 중단을 구분한다. 형식이 틀린 수신과 정상적인 같은 값 반복을 구분한다. |
| 압력 반응 | `pending / observing / suspected`를 기본으로 한다. 판단·해제 근거가 부족하면 `pending`으로 두고 과거 의심 기록을 유지한다. |

압력 반응의 계산식·시간창·상승폭·의심/해제 수치는 [PLAN.md §5](PLAN.md#5-실시간-상태-확인과-누설-의심-안내)의 미검증 초기 설정을 한 설정 파일로 옮긴다. 수치를 이 문서에서 다시 정의하지 않는다.

배치 확인 뒤 기준 구간을 모으고 가열 사건 뒤 추세를 평가한다. 새 구간, 범위 밖 값, 파싱 오류, 알려진 장치 이동은 계산창을 초기화한다. 뚜껑 열림 뒤에는 **다시 밀폐** 기록부터 기준값을 새로 모은다. 물 추가는 가열 중 조작으로 기록한다.

점검은 기록을 멈추거나 분석 행을 제외하지 않는다. 세션은 관측 상태가 바뀔 때 진단 사건을 한 번 생성하고 RunStore에 전달한다. UI는 해당 상태를 표시하며 사건을 다시 저장하지 않는다. 근거 시간창·계산값·설정 버전을 남기고, 이후 사용자가 사건 내용을 정정해도 당시 점검 기록은 당시 근거로 보존한다.

|---|---|
| 전체 CSV | 샘플 ID·구간·구간 경과시간·시간 출처·UTC 시각·온도·압력·유효성 표시를 포함한다. 기존 주요 열 이름 `timestamp / temperature_c / pressure_hpa`를 유지한다. |
| 선택 자료 CSV | 선택 범위에도 기본 원자료 열을 항상 포함하고 선택한 계산 열을 덧붙인다. 제외·유효성 처리와 실제 내보낸 행 수를 표시한다. |
| 전체 실험 JSON | 스키마 버전과 실험·샘플·사건·현재 작업 상태를 담는다. 장치 객체·DB 핸들·탭 잠금은 포함하지 않는다. |
| 그래프 PNG | `ui/chart-view.js`의 `exportPng()`로 현재 축·단위·범위를 포함한다. |

CSV는 실제 스프레드시트에서 읽을 수 있도록 UTF-8 BOM과 따옴표·쉼표·줄바꿈 처리를 적용한다. Papa Parse의 읽기·쓰기는 `data/files.js` 안에서 사용하며 숫자·열 이름·단위·참조의 검증은 실험 계약을 따른다. 불러오기는 기획안의 두 CSV 형식과 전체 실험 JSON을 지원한다. 기존 CSV에 없는 사건은 비어 있는 상태로 두고, 행마다 샘플 ID를 부여한다.

신규 CSV의 구간 경과시간과 시간 출처를 보존한다. 구형 CSV는 행 순서·수신 시각으로 구간 경과시간을 유도하고 `timeBasis=utc-derived`로 표시한다. 시각 역행·긴 공백에서는 구간을 나누며, 유도한 시간을 보존된 단조 시각처럼 취급하지 않는다. 선택 CSV는 내보낸 부분 자료로 다시 열고 원래 전체 실험을 복원한 것으로 표시하지 않는다.

JSON은 스키마·숫자·ID 참조·계산 열 의존성을 먼저 확인한 뒤 저장한다. 실험 ID가 충돌하면 새 ID로 가져오고 자식 레코드의 실험 ID도 함께 바꾼 뒤 출처 ID를 기록한다. 원자료·사건·작업과 원래 완료/중단 상태를 보존하되 활성 통신이나 탭 잠금은 복원하지 않는다. 미완료 자료를 이어 측정하려면 작성 권한과 새 연결을 확보하는 기존 재개 절차를 따른다.

CSV·JSON은 RunStore 스냅샷을, PNG는 현재 차트 표시 모델을 사용한다. 가져온 파일은 검증한 레코드로 저장하며 실제 수신처럼 재생해 조작·진단 사건을 새로 만들지 않는다. 브라우저의 다운로드 요청과 외부 파일 저장 완료는 별개로 안내한다. 다른 기기·출처로 옮기는 경로와 저장 범위는 [기획안 §6·§8](PLAN.md#6-브라우저-저장과-측정-분석-연결)을 따른다.

## 10 구현 순서와 완료 기준

### 현재 구현 범위 (M1 · 2026-10-11)

시작·준비·측정·분석 화면, 실제 BLE 입력 어댑터, 앱 내부 USB 설치, 프로그램 설정, 3D 메시지 어댑터, Chart.js 연결과 IndexedDB 스키마를 구현했다. 실제 V2와 사용자 연결 센서에서 **앱 내부 USB 설치 → Bluetooth 수신 → USB 분리 후 배터리 수신**을 확인했다. 실행과 검증 범위는 [README.md](README.md)에 기록한다.

M1에서 `measurement/reception-monitor.js`는 연결 확인과 최근 60초 표시용 캐시만 제공했다. M2에서는 세션이 이 관찰자를 재사용하고 모든 파싱 가능한 원자료를 RunStore에 따로 전달한다. 형식 오류는 사건으로 보존하며 유효 구간 이전의 범위 밖 수치도 버리지 않는다.

### M2 구현 상태 (2026-10-11)

- `session.js`: 샘플·구간 ID, 시각 불연속, 수신 중단·복구, 가열·물·장치 사건, 중복 종료와 종료 후 입력 차단.
- `run-store.js` / Repository: Web Locks, 1초 저장 일정, ID·revision 확정, 실패한 동일 묶음 우선 재시도, 충돌 시 전체 트랜잭션 취소, 종료 저장. 작성 잠금이 없으면 기존 실험은 읽기 전용이며 새 기록은 시작하지 않는다.
- 앱: 화면 이동 동안 기록 유지, 미완료 자료의 명시적 이어 측정·여기까지 분석, 완료 기록 열기, 저장 오류·CSV·임시 자료 인계. 재생 자료에 실제 BLE 입력을 섞지 않는다.
- 화면: 최근 60초·전체 구간 그래프, 조작 시각 점·기록 목록, 연속 스크롤 원자료 표, 전체 CSV. 순서를 건너뛰어도 가열은 배치·새 값 확인을 따로 요구한다.
- 저장소가 열림과 자료 저장 완료를 구분한다. 비정상 종료 뒤 복원은 마지막 완료 트랜잭션까지다. 한 번 열어 둔 읽기 전용 탭은 그 시점의 복사본을 보여 주며, 작성 권한 재시도나 새로 열기로 갱신한다.
- 브라우저의 실제 IndexedDB·Web Locks, 합성 640개 자료·2개 구간의 복원·종료·CSV를 확인했다. 실제 센서에서도 199개 저장 → 연결 해제·새로고침 복원 → 이어 측정·재연결 → 77개 추가 → 종료·276개 복원·CSV를 확인했다. 중단·재개·종료 사건과 두 구간을 보존했다. 재연결 도중 일시적으로 끊긴 상태를 관찰했으며 원인은 특정하지 않았다. 실물 수신 구간 합계는 약 51초이고 물 가열·장시간 검증은 남아 있다. 상세 근거는 README에 기록한다.

Workspace revision 저장 경계는 준비했지만 작업 UI·사건 정정·JSON·파일 가져오기는 M3, 누설 추세는 M4에서 이어 구현한다.

### 10.1 문서 다음에 할 일

| 단계 | 작업 순서 | 완료 기준 |
|---|---|---|
| M1 화면과 연결 뼈대 | 앱의 세 화면·공통 상태 → 최소 연결 화면과 프로그램 설정 → 3D 어댑터와 준비 안내 → 저장소 스키마 | 공식 도구 전송, 실제 BMP280 값, USB 분리 후 배터리 수신을 같은 흐름에서 확인한다. 준비·측정·분석 화면의 초점과 주요 행동을 화면에서 검토한다. |

전체 CSV는 M2에서 먼저 제공해 분석 도구가 개발 중일 때도 측정 자료를 스프레드시트에서 사용할 수 있게 한다. 기획안의 전체 기능 범위는 유지한다.

공식 전송과 배터리 수신의 실물 확인은 M1의 최소 연결 화면이 생기는 즉시 수행한다. 화면 연출을 다 만든 뒤로 미루지 않는다. 실물 확인을 기다리는 동안 저장·분석은 재생 자료로 구현할 수 있으며 실기 확인 상태는 별도로 남긴다.

### 10.2 필요한 검증

| 변경 영역 | 확인할 핵심 사례 |
|---|---|
| 3D 연결 | 단계 반복 적용으로 강조가 풀리지 않음, 현재 단계 복귀, 독립 안내·임베드 화면의 필요한 동작 |
| 통신과 세션 | 최초 수신, 오래된 콜백, 단절·재연결, 배터리 전환, 중복 종료 |
| 저장과 복원 | 저장 도중 새 수신·새 작업 revision, 실패 후 재시도, 확정 중 미저장 스냅샷, 사건 정정, 새로고침, 두 탭의 같은 실험 쓰기 |
| 분석 | 알려진 계산 결과, 분모 0, 일정한 X/Y, 기울기 0, 선택·필터·제외·복원, 결과 버전 불일치 |
| 점검 | 정상 비례/작은 압력 반응의 합성자료, 새 입력이 없는 tick, 냉각·작은 변화·수신 공백, 실제 추가 자료 |
| 파일 | CSV를 스프레드시트에서 읽기, JSON 왕복 후 ID·원자료·사건·작업 대응 |

변경한 모듈과 그 연결 부분을 확인하고, 마지막에는 준비부터 저장·분석까지 한 차례 이어서 사용한다. 이미 확인한 개별 검사를 단계마다 전부 반복하지 않는다. 처음 사용하는 교사나 학생이 어느 화면에서 추가 설명을 필요로 했는지 기록해 안내를 보완한다.

> [!NOTE]
> 구현 중에는 이 문서의 계약과 완료 기준을 함께 갱신한다. 사용자 경험이나 기능 범위를 바꾸는 결정은 기획안에도 반영하고, 세부 배치·함수 분해·표현 조정은 구현과 함께 정한다.

### 10.3 후속 UX 개선 항목

저장 상태 표시 개선 완료 (2026-10-11): 기록 가능한 측정 세션에서는 정상적인 저장 대기·저장 중·저장 완료 전환을 **자동 저장 중** 하나로 표시한다. 오류는 **저장 문제**로 우선 표시하며, 종료 후에는 실제 저장 상태에 따라 대기·진행·완료를 표시한다. 미완료 기록을 열기만 한 상태나 읽기 전용 상태는 자동 저장 중으로 표시하지 않는다. 내부 저장 주기와 실제 저장 완료 건수는 유지한다.

- [x] **UX-01 · 종료된 실험의 연결 안내와 버튼 상태 일치** (2026-10-11 구현, 재생 자료 UI 확인)
  - 재현: 측정을 종료한 뒤 같은 실험의 **장치 준비 → 수신 확인**으로 이동한다.
  - 현상: 장치는 연결되지 않았지만 연결 버튼이 비활성화되고, 안내는 여전히 “마이크로비트 연결을 누르세요”와 수신 확인 대기를 표시한다. 사용자가 연결 고장으로 오해할 수 있다.
  - 원인: 연결 버튼은 기록 가능한 세션에서만 활성화되며, 종료된 실험을 열거나 준비 화면으로 이동해도 새 측정 세션은 만들지 않는다. 준비 안내는 이 종료 상태를 반영하지 않는다.
  - 사용자 논의 후 적용: 종료 상태와 연결할 수 없는 이유를 표시하고 **추가 측정** 체크리스트로 같은 실험의 기록을 재개한다. **새 실험**은 별도로 유지한다. 비활성 연결을 누르라고 안내하지 않는다.
  - 확인: 완료 배지, 추가 측정 취소·확인, 조건 변경 메모, 일시정지·복원·재개·종료를 브라우저 재생 자료로 검증했다. 실제 장치의 새 일시정지 기능 확인은 별도 후속 확인이다.

- [ ] **UX-02 · 측정 종료 후 추가 측정 버튼의 발견성과 배치 개선** (2026-10-11 기록, 후속 UX 정리 시 검토)
  - 관찰: 사용자는 **측정 마치기** 옆에 **추가 측정**이 나타날 것으로 예상했으나, 현재는 상단 실험 관리 영역에 표시되어 기능이 없는 것으로 오해했다.
  - 검토 방향: 종료 후 **측정 마치기**가 같은 자리에서 **추가 측정**으로 바뀌는 방식을 우선 검토한다. 상단 공통 행동의 유지 여부와 종료 후 분석 화면에서도 재개 행동을 쉽게 찾을 수 있는지 함께 살핀다. 최종 배치는 후속 UX 정리에서 결정한다.
  - 완료 기준: 측정을 마친 사용자가 추가 측정 행동을 별도 설명 없이 찾고 조건 확인 팝업으로 이어갈 수 있다. 기존 체크리스트와 같은 실험에 기록을 추가하는 흐름은 유지한다.
  - 현재 범위: 후속 과제만 기록하며 화면과 동작은 변경하지 않는다.
