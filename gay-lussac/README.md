# 게이뤼삭 실험

**기체의 온도와 압력**을 측정하는 전용 실험 앱의 하위 프로젝트입니다. 3D 장치 준비, 공식 도구의 USB 프로그램 전송, 최소 측정 안내와 실시간 점검, 브라우저 저장, 학생 주도 분석을 연결합니다.

> [!NOTE]
> **M2 측정·자동 저장·복원·전체 CSV를 구현했습니다.** 자동·재생 검사와 실제 센서의 기록·재연결·복원·CSV 확인을 완료했습니다. M1의 앱 내부 USB 설치 → Bluetooth → 배터리 수신 실물 검증도 별도 완료 상태입니다. 물 가열 실험은 아직 수행하지 않았습니다.

## 실행

저장소 루트에서 Node.js로 로컬 서버를 실행합니다. 별도 패키지 설치·빌드는 없습니다.

```powershell
node gay-lussac/dev/serve.mjs
```

[로컬 앱](http://127.0.0.1:8765/gay-lussac/)을 노트북 Chrome·Edge에서 여세요. 다른 포트를 쓰려면 명령 끝에 포트 번호를 붙입니다. 서버는 `127.0.0.1`에서만 제공하며 종료는 `Ctrl+C`입니다. 상위 BLE·3D·차트·HEX 자원을 함께 사용하므로 저장소 루트를 제공해야 합니다. 파일을 직접 더블클릭하는 실행은 지원하지 않습니다.

2026-10-11에 자동 검사 13개와 Chromium에서 화면·3D 반복 적용·모의 BLE 전환·스키마를 확인했습니다. USB 검사는 실제 HEX·공식 해석기와 모의 연결로 해시 오류·다른 보드·취소·중복 클릭·전송 실패·완료 판정을 확인합니다. 실물 동작·센서 정확도 검증을 대신하지 않습니다.

```powershell
node --test gay-lussac/tests/*.test.mjs
```

`measurement/reception-monitor.js`는 최대 60초·6,000점의 표시용 캐시입니다. M2 원자료는 별도 RunStore에 보존하므로 이 표시 제한과 관계없이 전체 CSV·원자료 표에 남습니다. 화면 이동은 세션을 유지하며 새로고침 뒤에는 마지막 저장분을 열고 명시적으로 이어 측정합니다.

| 화면·파일 | 최근 60초/전체 시간 그래프와 구간 분리, 조작 시각 점, 원자료 연속 스크롤, UTF-8 BOM 전체 CSV |

2026-10-11 확인: 자동 검사 **21개** 통과. 실제 Chrome IndexedDB·Web Locks 검사 5개, 재생 자료 **640개·2개 구간**의 열기 → 이어 측정 → 조작 메모 → 측정 종료 → 페이지 이동 → 새로고침 복원 → CSV 다운로드를 확인했습니다. 다운로드 CSV를 별도 CSV 읽기 도구로 확인했습니다. 재생 자료는 `source=replay`로 분리하며 실제 BLE 수신을 덧붙이지 않습니다. 물 가열 실험·CSV의 Excel 화면 확인은 아직 수행하지 않았습니다.

같은 날 Windows Chrome에서 실제 `BBC micro:bit [gugav]`와 연결된 센서로 M2 저장 흐름을 확인했습니다. 실험 ID는 `aa96af28-274a-41e8-9714-f9afba1cb1c3`입니다. 준비 → 측정 → 분석 → 측정 화면 이동 중 기록이 이어졌고, 앱에서 연결 해제 후 **199개 저장 완료**를 확인했습니다. 새로고침으로 미완료 실험을 복원하고 **이어 측정**한 뒤 같은 장치를 재연결했습니다. 첫 재연결 선택 이후에는 연결이 끊긴 상태로 관찰됐으며 원인은 특정하지 못했습니다. 이후 실제 새 값 수신을 확인해 두 번째 구간에 **77개**를 추가했습니다. 측정 종료 후 **276개 전부 저장**, 분석 인계, 다시 새로고침한 뒤 동일한 자료 수·2개 구간·중단/재개/종료 기록 복원을 확인했습니다.

실물 CSV를 PowerShell `Import-Csv`로 별도 읽어 276행, ID 1–276의 누락·중복 없음, 구간 1의 마지막 ID 199 → 구간 2의 첫 ID 200과 구간 경과시간 0부터 재시작, UTF-8 BOM, 압력 원값 보존을 확인했습니다. 수신 범위는 한국 시각 20:40:33.812–20:46:07.019이며 중간 연결 대기를 포함합니다. 두 구간의 실제 수신 경과시간 합은 약 51초입니다. 이 확인은 짧은 실물 기록·저장 확인이며 장시간 안정성이나 가열 실험의 검증은 아닙니다.

이후 사용자 요청으로 표의 페이지 버튼을 없애고 연속 가상 스크롤로 변경했습니다. 재생 자료의 처음·중간·마지막 640번째 행까지 이동과 역방향 이동을 확인했습니다. 640행 모두의 스크롤 범위를 유지하면서 실제 DOM에는 확인한 화면 크기에서 18–27행만 표시됩니다.

반복해서 결함을 찾을 수 있는 검사는 두 경계로 유지합니다.

- `node --test gay-lussac/tests/*.test.mjs`: 세션·저장 중 추가 입력·실패/응답 유실·스냅샷·중복 종료·CSV·자동 저장.
- [브라우저 저장 경계 검사](http://127.0.0.1:8765/gay-lussac/tests/browser.html): 실제 DB 트랜잭션 취소·동일 묶음 재시도·작성 잠금·재개. 검사 DB는 `bme280.gay-lussac.tests`이고, 재생 자료 만들기는 명시적 버튼을 누를 때만 앱 DB에 별도 실험을 추가합니다.

전체 CSV는 수신 시각(UTC), 샘플·구간 ID, 구간 경과시간, 시간 출처, 온도·압력 원값과 유효성 열을 포함합니다. 표의 수치 표시는 소수 둘째 자리로 정리하지만 CSV는 원값을 유지합니다. 조작 기록은 이 브라우저에 저장되며 사건을 포함한 전체 JSON은 M3에서 제공합니다.

열린 실험 전체를 RunStore 메모리에 보유합니다. 비정상 종료 시 미완료 저장분까지 복구된다고 보장하지 않으며, 저장 오류 중에는 탭을 유지하고 다시 저장하거나 CSV로 보관합니다. 분석 계산·사건 정정·JSON·가져오기는 M3, 누설 추세 진단은 M4 범위입니다.

후속 변경 확인 (2026-10-11): 일시정지·추가 측정을 포함한 자동 검사 **25개**, 실제 브라우저 저장 경계 **6개**를 통과했습니다. 재생 자료 화면에서 체크리스트 취소, 변경 메모 요구, 추가 측정, 일시정지의 새로고침 복원, 재개·재종료를 확인했습니다. 분석 표는 적용 시점의 자료를 유지하며 새 수신은 **새 자료 적용**으로 반영합니다. 이 표 보기 범위의 영구 저장과 실제 분석 도구는 M3에서 구현합니다. 새 일시정지 기능 자체의 실제 장치 검증은 아직 수행하지 않았습니다.

종료된 실험의 연결 안내 문제 [UX-01](DESIGN.md#103-후속-ux-개선-항목)은 완료 배지·추가 측정 행동·종료 상태 안내로 수정했습니다.

### 실물 확인 결과와 재현 절차

USB 설치 확인 파일: `firmware/bme_1.2.hex`, SHA-256 `435fb8f8d160da517f3924d34cb22294a5d9e3c2aadca6bb4f5b305346e97186`. 확인일은 2026-10-11이며 Windows Chrome·micro:bit V2·사용자가 연결한 센서 조합에서 아래 2–4번을 통과했습니다. USB 분리는 사용자 확인에 근거하며 전원 종류를 앱이 자동 감지한 것은 아닙니다. 센서·확장 보드의 정확한 제품명은 별도로 기록되지 않았습니다.

첫 Bluetooth 연결에서는 3초 내 값이 없어 해제됐고, 사용자가 연결 오류를 바로잡았다고 알린 뒤 재연결에서 정상 수신했습니다. 원인은 특정하지 않았으며 이 결과를 근거로 대기시간·펌웨어 계산식을 변경하지 않았습니다. `program-config.js`의 `communication-verified`는 설치·데이터 수신·배터리 동작을 확인했다는 뜻이며 센서 정확도나 모든 보드 조합의 검증을 뜻하지 않습니다.

1. **처음부터 준비하기**에서 실제 모듈의 단자 이름과 배선을 확인합니다.
2. 앱의 **USB로 프로그램 설치**를 누릅니다. 처음에는 USB 장치를 선택하며 지정된 `bme_1.2.hex`가 파일 선택 없이 전송됩니다. 같은 페이지에서 선택한 장치를 재사용하며, 새로고침·장치 변경 시 다시 선택할 수 있습니다.
3. 장치를 연결하고 새 온도·압력값의 지속 수신을 확인합니다.
4. 배터리 연결·USB 분리 후 확인 버튼을 누르고 이후의 새 값으로 재확인합니다. 필요하면 다시 연결합니다.
5. 다른 장치 조합에서도 같은 절차로 확인하고 센서·확장 보드·브라우저·HEX 해시와 결과를 기록합니다.

HEX의 기존 계산 문제 수정은 이번 M1 범위에서 보류했습니다. 수신 조건 통과는 연결 확인이며 프로그램 버전이나 센서 정확도에 대한 보증이 아닙니다.

## 구현 순서

1. **M1:** 화면·연결 뼈대, 기존 3D 안내 연결, 공식 전송과 배터리 상태 수신 확인.
2. **M2:** 측정·지속 저장·수신 점검, 분석으로 자료 인계, 전체 CSV.
3. **M3:** 자유 분석과 작업 복원, 나머지 파일 입출력.
4. **M4:** 누설 의심 추세 점검, 추가 실험 자료 검토, 처음부터 끝까지 사용 흐름 확인.

구현은 [설계 문서의 단계별 완료 기준](DESIGN.md#10-구현-순서와-완료-기준)을 따라 진행하고, 모듈 연결과 의존성 추가에는 [구현 경계와 라이브러리 선택](ARCHITECTURE.md)을 적용합니다.

- [범용 측정 도구](https://cho-wh.github.io/bme280/)
- [BMP280 배선 3D 안내](https://cho-wh.github.io/bme280/bmp280-wiring/)
- [공식 micro:bit HEX 전송 도구](https://microbit.org/tools/webusb-hex-download-tool/)

배포 시 실행 경로는 `/bme280/gay-lussac/`를 사용합니다. 현재 변경은 로컬 브랜치의 구현이며 배포하지 않았습니다.
