# 게이뤼삭 하위 프로젝트 구현 안내

이 폴더의 문서와 코드를 수정할 때 적용한다. M1 핵심 실물 흐름을 확인했고, M2 측정·저장·원자료 인계·전체 CSV를 구현했다. M2의 자동·브라우저 검증과 실물 확인 상태를 구분하며, 검증 범위와 후속 구현은 [README.md](README.md)를 따른다.

## 기준 문서

- [PLAN.md](PLAN.md): 사용자 확정 결정 D1–D5, 기능 범위, 실험·학생 UX의 기준.
- [DESIGN.md](DESIGN.md): 화면·상태·입출력 계약과 단계별 완료 기준.
- [ARCHITECTURE.md](ARCHITECTURE.md): 상태 소유권, 의존 방향, 라이브러리 선택과 근거.

## 구현 원칙

- 열린 실험 자료와 저장 상태는 RunStore를 통해 다룬다. Repository는 DB 접근을 맡는다.
- Workspace는 분석 작업을 수정하고 revision별 복사본을 RunStore에 전달한다. 저장 완료 revision과 계산 입력 revision을 구분한다.
- 측정 세션은 표준 수신 입력을 받는다. 진단 규칙은 상태·시각을 인자로 받고 결과를 반환한다.
- 원자료는 추가 저장하고, 분석의 선택·제외·계산 결과와 구분한다. 표시용 행 번호 대신 sampleId로 자료를 참조한다.
- 화면의 정리와 실험 종료를 구분한다. 화면 전환 동안 세션과 미저장 자료의 수명을 유지한다.
- 라이브러리는 해당 어댑터 안에서 사용하고, 공개 계약에는 일반 데이터와 행동 함수를 전달한다.
- 변경할 때마다 모듈의 책임·의존 방향·추상화 경계를 확인한다. 동일한 로직·UI 요소·자원을 새로 만들기 전에 상위 원본 앱과 하위 프로젝트의 재사용 가능성을 먼저 살핀다. 기존 3D·통신·차트 자원은 확인된 연결 지점에서 재사용하고, 실제 필요한 범위부터 공통화한다.
- 외부 배포 파일을 추가할 때 정확한 버전·출처·해시·라이선스를 기록한다.
- 변경한 동작과 연결 경계를 검증한다. 문서만 바꿀 때는 계약의 일관성과 링크를 확인한다.
- 일회성 확인용 검사·스크립트를 관행적으로 누적하지 않는다. 단계별 작업을 마칠 때 검사의 결함 탐지 효과와 유지 비용을 검토하고, 중복되거나 구현을 그대로 확인하는 형식적 검사는 통합·정리한다. 핵심 동작과 재발 가능성이 있는 결함을 검증하는 검사는 유지한다.
- 구현 계약이 바뀌면 해당 설계 문서를 함께 갱신한다. 사용자 경험·기능 범위의 변경은 기획안에도 반영한다.
